# Contributing to the Multi-Agent Travel Planning System

## Workflow

1. Start with an issue that defines the behavior or integration being changed.
2. Create a focused branch from `main`.
3. Keep agent routing, state changes, and MCP integrations reviewable.
4. Test both happy paths and API/provider failure paths.
5. Update the architecture documentation when graph topology or agent responsibilities change.
6. Never commit provider API keys or database credentials.

## Useful branch prefixes

`feat/`, `fix/`, `docs/`, `test/`, `chore/`.
